# Live Unreal animal interaction test

This is actual Unreal simulation, not the earlier Blender/background composites. Existing lion/cat models and source movies are preserved. Imported assets live in a new `/Game/PhysicsLab/package_<timestamp>` folder; lab.json records the independently saved level.

Pipeline: export_physics_characters.py uses the existing Blender performance export helper to bake the meadow run and sample facial curves internally. import_physics_characters_unreal.py imports native skeletal assets and bakes facial curves onto matching AnimSequences. Import metadata reports lion height 185 cm and cat height 150 cm, one skeletal mesh each, with 17/19 morph targets. These counts do not certify facial appearance.

build_physics_lab_unreal.py creates actual Character actors with collision capsules, gravity, movement without a controller, a 10-degree ramp, a platform, a 25 cm step, a wall, and an 18 kg rigid-body crate. Facial/skeletal animation plays on their native components. The capsule is sized from each character height and the mesh is offset from its imported bounds. There is no runtime foot IK, plant locking, gait-to-distance matching or hit-reaction blend yet. Running continues while blocked; do not mistake collision response for natural acting.

run_physics_test_unreal.py starts Simulate in Editor and adds real movement input. Telemetry records actual world time, actor positions, velocities, falling state and capsule bottoms every ~0.1 seconds. A one-time impulse is applied only when the lion is within 3 cm of the crate capsule-contact boundary and forward speed is below 30 cm/s. This proximity-plus-stopped-speed trigger is a prototype; replace it with bound engine hit events in the production controller. The rigid body responds through Unreal physics. There are no teleported path keys or fabricated collision positions.

Measured final run: lion travels approximately 23.5 m, cat 31.9 m; crate displacement approximately 2.33 m. The cat stops at the wall. simulation.json stores samples, event and summary; capture.json records real screenshot times and video decode confirmation. The earlier failed ramp entrance test is preserved in simulation-first-ramp-test.json. Surface probing identified a rotation-axis error; the corrected builder uses named Rotator fields, avoiding ambiguous positional ordering.

capture_physics_test.py records live viewport screenshots with a following camera, encodes physics-test.mp4 and fully decodes it. Screenshot timing is variable and low rate, so this is a mechanics preview, not a cinematic render. The callback pauses the simulation when complete; end_physics_test_unreal.py explicitly ends it. Always end a prior simulation before rebuilding/retesting. These are development scripts, not a persisted gameplay Blueprint/controller: a freshly opened level needs the runner to move the characters.

Next required work: gait-aware foot traces, pelvis adjustment and Two Bone IK/Control Rig; foot-plant curves and speed matching; idle/stop/recoil transitions; hand-contact constraints; physics-event routing, impacts and audio. Then render a properly staged movie shot using Sequencer/Movie Render Queue. General terrain use and character-to-character impacts have not been validated.
