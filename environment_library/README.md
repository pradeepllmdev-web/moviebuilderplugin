# Movie environment library starter

The catalog has six outdoor starter recipes plus planned categories needing additional builders/assets. Live demos are now saved in the independent LatestSceneVerification Unreal project under /Game/EnvironmentDemos, with previews and build reports in demos/. The local demo studio runs at http://127.0.0.1:8521 and its dedicated editor bridge at http://127.0.0.1:8520. This is separate from the 3dobjectnew website.

Current demos: golden riverbank with birch trees, misty Nordic forest and rocky valley. All were built using existing assets; no paid generation or downloads. A complete test analyzed the forest preview image locally with Qwen3-VL, produced a validated recipe, built a DIFFERENT saved Unreal level, and captured its preview. This tests reference-guided approximation, not exact reconstruction or a user-provided reference.

Use the demo studio to upload PNG/JPEG, analyze locally, review/adjust biome, terrain, lighting, river, mountains, density and seed, then build. The builder saves a new level and recipe rather than overwriting an earlier map. It supports natural outdoors; architecture and unsupported categories are rejected or reported as additional requirements. Image analysis identifies appearance and selects a procedural recipe; it does not solve exact object placement or camera calibration.

Optional layout controls are now implemented. The page offers a top-down drawing grid with real width/depth in metres; river and path points, circle forest regions, clear filming areas, wooden bridge placement, and camera position/target. A top-view image can be loaded UNDER the drawing as a guide; it is not automatically segmented or reconstructed. Coordinates use top-left (0%,0%) to bottom-right (100%,100%), mapped to centered Unreal XY centimeters with image Y inverted. The server validates and compiles these coordinates before building. Region density controls trees, while a separate scatter keeps ground vegetation outside those tree regions.

Worked example: refresh the page and use "Try this image and plan", then "Analyze image", review the controls and layout, and "Build new Unreal environment". The page shows the source image, plan and final Unreal preview under "Worked example". The test uses the existing forest image plus explicit river/path/bridge constraints to demonstrate customization, not exact image reconstruction. Previously verified analysis of the identical image is cached to reduce repeated processing. New images invoke local vision and may take longer. Saved records include the source hash, original layout, compiled coordinates, recipe, saved level and preview.

To launch: open the independent Unreal project with start_demo_editor.py via ExecCmds, then run studio_server.py with server Python. The start script switches the bridge to 8520 and starts a blank map without saving over the current level. The startup command requires the existing editor/plugins/assets installed on this machine. The local demo server is session-based; saved level/recipe/preview files persist, but in-memory job polling does not survive a server restart.

Tests: test_reference.py covers supported/unsupported recipes, invalid parameters, safe identifiers and grounded missing-feature reporting. test_layout.py covers axis conversion, scale, bounds, invalid routes and bridge references. verify_image_pipeline.py exercises upload/analyze/build/preview. verify_layout_pipeline.py additionally checks the actual Unreal river coordinates and creation of a bridge, path and two forest regions. JavaScript is syntax-checked; interactive browser automation was blocked by browser policy, so the browser UI was not clicked through by the agent. No vertex/face/model arrays are logged into prompts.

Shared ownership: 3dobjectnew should own the environment records, references, recipes, thumbnails, versions and movie/shot links. The Unreal plugin should own Unreal asset resolution, terrain/water/foliage construction, actors, levels, lighting and preview/render operations. Blender remains the character performance authoring tool. This starter lives in moviebuilderplugin for review and has not been installed into either application.

Categorize primarily by physical location. Add separate tags for genre, style, period, season, weather, time and action requirements. A horror forest and a cheerful forest may share the same location recipe while changing lighting, density, fog and dressing. Interiors need room/architecture builders, not a biome override.

Environment instances must keep asset choices and layout fixed across shots. Store a seed plus recipe version and resolved assets; the seed alone does not preserve continuity when asset inventories or generation code change. Shot records refer to an environment instance and can override camera, lighting and temporary dressing without regenerating the world.

Reference-image customization should infer visible layout, horizon, camera perspective, terrain, structures, vegetation, material palette, weather and light direction. Mark scale and unseen areas as uncertain. Resolve against an asset registry containing paths, semantic roles, style, dimensions, collision support, license and availability. Do not silently substitute incompatible asset types or pretend a single image specifies a full 3D world.

Reserve actor zones, walking/running corridors and camera paths before dressing. Keep close-up foreground assets at high quality, with lower-cost background detail. Validate ground contacts, collision, clearance, camera visibility, water boundaries, material quality and shot-to-shot consistency. Preview from both the reference-matched camera and other angles; a single good image does not establish a usable movie set.

Initial delivery sequence: inventory existing assets and engine/plugin capabilities; build and save the riverbank, forest and meadow as separate levels; capture a consistent preview set; add editable reference-to-recipe controls; then add mountain and woodland variants. Expand with an interior room and village/city street kits for broader story coverage. Do not buy or download additional assets automatically.
