# Special Delivery, Extra Courage

A 21-second, four-shot native Unreal delivery scene with Leo and Amber, rendered through Movie Render Queue at 960 × 540, 24 fps (504 frames). Output: special-delivery.mp4, soundtrack.wav, captions.vtt and four inspection images. The local studio embeds the video with optional/default English captions. Original models, the house source, and earlier films remain preserved.

1. prepare_delivery_dialogue.py creates four new free offline SAPI lines and viseme tracks.
2. export_delivery_actions.py retargets six existing motion-library clips and authors two-hand carrying poses with analytic arm IK. Walk speed comes from the measured retargeted stride. The flat-ground foot lock is solved on a virtual moving path and then exported in place for Unreal movement. Source animation is placed on an NLA strip so the foot-lock layer is not masked by Blender's active action. No model geometry is printed.
3. import_delivery_actions_unreal.py imports the six action animations against the existing native animal skeletons. build_delivery_scene_unreal.py opens the existing house and saves a separate copy with actual Character capsules, a 12 kg rigid-body crate, and a carried parcel. The terrace provides a real 20 cm step above surrounding ground.
4. run_delivery_scene_unreal.py starts actual Unreal simulation. Character movement uses stride speed × playback rate; collision stops movement and switches to recoil/idle. Both characters bind the supported ActorHitSignature delegate. The component-hit getter is unavailable in this editor's Python interface; there is no proximity-trigger fallback. Cat and lion collision events explicitly apply art-directed impulses to the crate, which then responds through physics. The recorded sweep-hit normal impulse is zero, as expected for these movement hits; the crate motion is from the applied impulses, not a measured solver impulse. The parcel follows the actual wrist midpoint and remains carried through recoil; no rigid finger-grasp constraints are implemented.
5. bake_delivery_sequence_unreal.py samples action poses and facial curves at 24 fps, then bakes recorded character, crate, parcel and camera transforms into a new Level Sequence. Body curves retain the authored action timing. Recorded physics transforms are interpolated from approximately 10 Hz telemetry. Movement/rigid-body simulation is disabled for deterministic replay. Actor scales are preserved. Sequence references are repaired after copying/saving the level; repair_delivery_bindings_unreal.py verifies all ten bindings resolve.
6. render_delivery_mrq_unreal.py runs the task's dedicated Movie Render Queue job. Native PNG frames use one temporal and one spatial sample; this is a preview-quality render. An initial output-setting mismatch and invalid saved-level binding were corrected. The first invalid render is preserved for diagnostics and not published; the final output directory is in mrq-result.json. All four final shot samples were visually inspected.
7. finish_delivery_movie.py checks all 504 frames, mixes dialogue with quiet original synthesized music, timed footsteps and hit sounds, encodes H.264/AAC and fully decodes the MP4. verify_delivery_curves_unreal.py checks the full jaw curve against speech weights at every frame.

Final live telemetry: cat travels approximately 2.98 m, lion 1.34 m; crate moves approximately 0.82 m. Actor-hit events occur around 5.62 and 10.63 seconds. Exact evidence is in simulation.json. Flat-ground source foot-drift sums improved from 13–17 cm to 4–8 cm per measured plant-span set (actions.json). That metric is the source clip's sum of maximum plant-span excursions, not a guarantee that every rendered foot stays within that distance or an engine terrain-contact measurement.

Still pending: general runtime terrain-adaptive foot IK/pelvis compensation, better foot/hand contact and finger grasp, more natural turn/recoil blends, richer set dressing/materials, higher-sample cinematic output, and integration into the main 3dobjectnew production workflow. The local scripts are reusable development tooling, not a universal completed character controller. Rebuilding animation import folders uses timestamped sources; scene/sequence creation saves unique versions. Rerunning finish intentionally replaces the demo MP4. The render queue script reuses the single DeliveryMishap job created in this dedicated editor and rejects other queue entries.
